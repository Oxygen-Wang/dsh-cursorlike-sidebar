# 撤销、恢复与操作反馈

更新：2026-10-18。入口：[分类需求索引](requirements-zh.md)。

## 交互原则

- 高频动作有结果提示，有明确的后退路径；用户不必在几秒内抢点撤销。
- 文件操作历史与编辑器文字历史分开。文件区 Ctrl/Cmd+Z 撤销，Ctrl/Cmd+Shift+Z / Ctrl+Y 重做；输入框、聊天、终端和编辑器保留自己的按键行为。
- 撤销后仍可重做。新的文件操作会建立新分支，旧分支的恢复数据不会立即清理。
- 冲突时保留双方文件，显示原因并允许解决冲突后重试，不能静默覆盖。
- 文件操作先保护未保存草稿，耗时请求中禁用重复提交，切换会话后不接收旧界面结果。

## 本轮实现

- [x] 移动与重命名：沿原路径撤销/重做，复用已有打开标签的路径协调。
- [x] 删除：改为移到恢复区，撤销可恢复文件、整个目录和符号链接；不执行永久 unlink/rm。
- [x] 复制与新建：撤销时把产生的内容收进恢复区，重做恢复同一份内容，不重新复制已变化的源文件。
- [x] 新建/复制之后在插件内保存的修改，撤销后仍被保留；保存导致的 inode 替换会同步到历史身份记录。
- [x] 批量移动、复制、删除分组为一步。只完成部分的批次，成功部分仍有可撤销记录。
- [x] 先检查整批路径冲突，再开始回放；回放中失败保留原步骤，可重试，已完成的路径不重复搬运。
- [x] 新增文件区撤销/重做按钮、快捷键、持续显示的结果提示和最近 20 步的操作记录面板。
- [x] 历史写到磁盘，按工作区和会话隔离，页面刷新/服务重新创建后读取原栈；没有 10 秒倒计时。
- [x] 目标已存在、源文件被不同条目替换、旧窗口请求过期时拒绝覆盖；记录保留供重试。
- [x] 会移走未保存文件的删除/撤销会先提示保存；输入框里的 Ctrl+Z 不触发文件撤销。
- [x] 恢复文件时可重新打开文件；恢复目录时重开当前文件窗口记住的原生文件标签。跨页面重启后的标签布局、光标恢复不包含在此项。
- [x] 三种文件视图共用后悔机制，恢复区不混入文件树和递归文件名搜索。
- [x] 本轮新增文案进入全部语言词典，完成项保留对应回归测试。

## 实现与扩展接口

Host：`src/file-history.ts` 记录可逆的路径迁移；浏览器类型位于 `src/file-history-types.ts`。

- 现有 `fs.rename`、`fs.transfer`、`fs.mkdir`、`fs.createFile`、`fs.remove` 自动进入历史。
- 新增 `fs.history`、`fs.undo`、`fs.redo`；回放携带 expectedId，避免旧窗口撤销了另一件事。
- 批量请求可携带 historyGroup，将同一批的成功项归入一步。
- 默认恢复区在工作区父目录的 `.dsh-cursorlike-recovery/<工作区摘要>/`，不自动删除备份。父目录无写权限或跨设备搬运失败时报告错误，原条目保持可用；本轮没有“复制后永久删除”的跨盘降级。
- 历史元数据通过临时文件 + rename 写入；移动/删除先登记路径，再搬运。重试依据文件身份和实际位置识别已完成部分。
- 编辑器保存接入身份更新，不将每次保存额外塞进文件操作撤销栈；文字编辑仍由编辑器的历史处理。
- UI：`use-file-history.tsx`；成功操作通知同工作区/会话的 Files 窗口更新历史。恢复/删除/移动效果通知标签页并刷新文件区。
