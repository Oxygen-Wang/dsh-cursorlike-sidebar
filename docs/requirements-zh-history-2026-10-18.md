## 1. 选中文字 → `Ctrl+L` / 拖动到主窗口，改成“文件 + 行号”引用

### 1.1 目标

用户选中一句话/一段代码后：

- 按 `Ctrl+L`（macOS `Cmd+L`）；
- 或者把选中的文字拖到主聊天窗口；
- 或者点“添加到对话”图标；

三种入口都插入**同一份引用**，不再默认插入整段代码块。引用要能看出：

1. 这是哪个文件（`@文件`）；
2. 这句话在第几行到第几行；
3. 可选保留选中文字（见 1.3 的选项）。

### 1.2 格式（已确认 A）

| 方案 | 插入示例 | 结论 |
|---|---|---|
| **A. 原生 chip + 行号后缀** | `@src/client/Foo.ts line 12-18` | **已确认**：`@src/...` 是 DSH 原生文件 chip，可点击；行号是普通文本，兼容性最好 |
| B. DSH 行号链接 | `@src/client/Foo.ts#L12-L18` | 备选，暂不做；需验证 DSH 输入框/消息是否识别 |
| C. 纯文本 | `src/client/Foo.ts:12-18` | 不采用 |
| D. 现状 | ```` ```src/client/Foo.ts:12-18 + 选中代码 ```` | 不采用 |

**实现形态**：先插入工作区相对的 `@file` chip，再追加 ` line 12-18`；单行写 ` line 12`。
- 文件在工作区外时，使用绝对路径（或退化为纯文本 `@绝对路径 line ...`，需确认）。
- chip 使用现有 `insertFileReference()`，保证和 DSH 原生 `@` picker 一致。

### 1.3 选中代码正文（默认不附，无行号时附内容）

- **默认只插入引用**：`@src/client/Foo.ts line 12-18`。
- 不默认插入 fenced 代码块；如后续需要，再加可选的“附代码”开关或 `Ctrl+Shift+L`。
- **例外：无法定位行号时**（Markdown 预览映射失败、目标在工作区外等），插入 `@file` 后直接附上选中内容，不再只剩路径。
- 这样草稿更短，Agent 仍可通过 `@file` 读取文件；行号告诉它看哪一段。

### 1.4 行号规则

- 单行：`line 12`。
- 多行：`line 12-18`（1-based，闭区间）。
- 选区跨空行/整行：按选区起止行。
- 无选区：当前光标所在行。
- Markdown 预览：用渲染文本反查源码行；找不到唯一匹配时**只写 `@file`，不猜行号**。
- 行号来自“当前文件内容”，不是 Git 旧版本。

### 1.5 拖动行为

- 编辑器/预览里拖选中的文字到主窗口：插入与 `Ctrl+L` 完全相同的引用。
- 文件树拖文件到主窗口：保持现有 `@file` 引用行为。
- 拖到聊天输入框的“插入位置”：沿用现有草稿插入逻辑（当前是追加到末尾；DSH 0.2.1 的 Lexical 输入框暂不做光标级插入）。
- 拖动数据里需要带上 `path`、`startLine`、`endLine`、可选 `text`，不能只带一段已经拼好的字符串。

### 1.6 交互细节

- 添加后**不抢焦点**：保留在编辑器/文件树，方便连续按 `Ctrl+L` 加多段（与 Cursor 的“添加后聚焦聊天”不同；如果希望聚焦，可加设置）。
- 重复按 `Ctrl+L`：允许重复添加；不做去重。
- 浮动按钮/拖拽/快捷键共用同一个 payload 构造器，避免三种入口格式不一致。
- 悬浮按钮的 tooltip 从硬编码中文改为本地化文案 + `Ctrl+L`。

### 1.7 验收

- 选中第 12-18 行，`Ctrl+L` → 草稿出现 `@文件 line 12-18`，不含整段代码。
- 无选区，`Ctrl+L` → 当前行引用（`@文件 line 12`）。
- 滚动让浮动按钮消失后，`Ctrl+L` 仍可用。
- 同一段文字拖到主窗口 → 与 `Ctrl+L` 结果一致。
- 文件树里按 `Ctrl+L` 仍插入 `@file` chip，不会误插编辑器旧选区。
- Markdown 预览选区可用；无法定位行号时退化为 `@file`。

### 1.8 待确认

1. 文件在工作区外时，行号引用用绝对路径，还是退化为纯文本？建议绝对路径。
2. 是否要加“添加后聚焦聊天输入框”设置？默认建议关闭。

## 2. 忽略文件/文件夹（侧边栏不显示）

### 2.1 目标

- 在文件树工具栏（上传文件/上传文件夹旁边）增加一个“忽略”图标。
- 可以把不重要的文件/文件夹快速加入忽略列表，侧边栏文件树和文件搜索不再显示。
- 支持 `.ignore` 文件，并能导入/兼容 `.gitignore`、`.cursorignore` 等规则。
- 忽略只影响侧边栏显示，**不删除、不移动、不修改**磁盘文件。

### 2.2 交互设计

**入口**

- 工具栏新增 `IconEyeOff`（或“忽略”图标），位置在上传文件夹按钮右侧。
- 点击打开小弹层（popover），展示：
  - 当前生效的规则（chips），每条带来源标签：`手动` / `.ignore` / `设置`；
  - 输入框：添加一条规则；
  - “导入忽略文件”按钮：读取选中的 `.gitignore` / `.cursorignore`，把规则**合并进 `.ignore`**（只导入一次，不持续读取）；
  - “显示被忽略项”开关（打开后忽略项以半透明行显示，而不是完全消失）；
  - “清除手动规则”。
- 文件树多选栏增加“忽略所选”；右键菜单也加一项，和现有“删除/重命名/复制路径”并列。

**拖拽**

- 图标本身是 drop target：把文件/文件夹从文件树拖到图标上 → 把它的**工作区相对路径**加入忽略规则。
- 拖拽时图标高亮，显示“忽略 `path`”提示。
- 与现有拖拽引用不冲突：拖到聊天输入框仍是引用；拖到忽略图标才是忽略。
- 也可以把 OS 文件（外部文件）拖到图标上？不建议：外部文件不在工作区，无法生成稳定规则；仅支持工作区内的树行。
- **已实现第一版**：工具栏 `.ignore` 眼睛图标是 drop target；拖入后把相对路径追加到根 `.ignore`（目录带 `/`），去重并刷新；点击图标直接打开 `.ignore`。尚未做拖拽提示文案和“忽略所选”多选。

**显示策略**

- 默认：被忽略的条目完全不出现（树和搜索结果一致）。
- “显示被忽略项”：条目出现但半透明/带删除线（参考 quietpet 的 `opacity:.55`），方便临时查看。
- 该开关是否持久化：建议**按会话/工作区记忆**，不要全局永久打开。

### 2.3 规则来源与优先级

已确认：**实时读取 `.ignore`**；`.gitignore` / `.cursorignore` 只通过“导入”合并，不自动读取。

优先级（从高到低）：

1. 临时“显示被忽略项”开关（只影响显示，不改变规则）；
2. 用户手动忽略（通过图标/多选/右键添加；**建议**写入根 `.ignore`，待确认）；
3. 工作区根 `.ignore`；
4. 子目录 `.ignore`（靠近文件的规则优先；支持 `!` 反向选择）；
5. 设置页的全局排除模式；
6. 内置默认（`.DS_Store`、`Thumbs.db`）。

规则语义：

- 支持 `.gitignore` 语法：`#` 注释、`!` 反向选择、`/` 锚定、`*`/`?`/`**`、目录尾部 `/`。
- 逐目录读取 `.ignore`：子目录规则只作用于该子树，靠近文件的规则优先（与 git 一致）。
- 手动忽略的路径写成**字面路径**并转义 glob 元字符（`[]*?!`），避免误伤同名文件。
- 被忽略的目录不再向下遍历（性能）。
- 忽略规则同时作用于：文件树 `fs.tree`/`fs.trees`、名称/内容搜索 `fs.search`、面包屑折叠判断。
- **不影响** Git 状态、Git diff、`dsh-diff-approval` 的变更列表。

### 2.4 `.ignore` 文件与导入

**实时读取 `.ignore`（已确认）**：

- Host 在列目录/搜索时读取工作区根及子目录的 `.ignore`，实时过滤；
- 改 `.ignore` 后，下一次树/搜索请求即可生效（缓存 key 带 mtime）；
- 支持子目录 `.ignore`，就近规则优先；
- 单文件读取上限 64 KiB，规则条数上限，非法行静默跳过。

**导入其他 ignore 类型（已确认：只导入，不自动读取）**：

- 弹层提供“导入 `.gitignore`” / “导入 `.cursorignore`”；
- 读取所选文件内容，把有效规则**合并写入根 `.ignore`**，并在导入块上方加注释：
  ```
  # imported from .gitignore (2026-10-17)
  ...
  ```
- 去重；不覆盖已有规则；不自动改写 `.gitignore` / `.cursorignore`；
- 导入后可手动编辑 `.ignore`，后续以 `.ignore` 为准。

**手动忽略写在哪里（建议，待确认）**：

- 建议写入工作区根 `.ignore`，加一个受管块：
  ```
  # Added by CursorLike Sidebar
  /dist/
  /coverage/
  ```
- 这样规则可提交、可共享、和 `.ignore` 单一来源一致；
- 如果不想污染工作区，可改为插件数据，但需要在 UI 中说明“规则不进 `.ignore`”。**需确认**。

### 2.5 作用域与持久化

- 现有 `explorerExclude` 是**全局**偏好，适合 `.DS_Store` 这类通用规则。
- `.ignore` 天然是**按工作区**的。
- 建议：
  - 手动忽略写入当前工作区根 `.ignore`，天然按工作区隔离；
  - 全局排除模式继续保留，作为跨工作区默认；
  - “显示被忽略项”按会话/工作区记忆（建议按工作区）；
  - 不同会话切换工作区，规则不串台。
- 需确认：如果手动规则不写 `.ignore` 而是插件数据，则必须按工作区 key 存储。

### 2.6 Host/Client 技术要点

### 3.8 Diff 行内“保留 / 撤销” + 快捷键 + 撤销机制（已实现，2026-10-18）

> 已落地：最后一个改动行后的内联 CodeMirror widget（保留/撤销条随内容滚动，不再固定在编辑器底部）；`Ctrl+K` 保留、`Ctrl+J` 撤销、`Ctrl+Z` 撤销上一步（无时间限制）。数据源是本插件检测到的编辑器内容变化，不等同于 `dsh-diff-approval` 的待审列表。
>
> **2026-10-18 修复（真实链路）**：`EditorHost` 的 agent 写入自动刷新原先先置 `loading` 再重建 viewer，`TextEditor` 的改动检测因此永远不触发（组件级测试能过、真实页面不出现）。现在改为**静默就地刷新**：不 unmount viewer，新的 `content` 由 `TextEditor` 以 `Transaction` 应用到现有文档（`addToHistory: false`），保留滚动/光标/撤销历史；改动行加绿色（新增）/蓝色（修改）行内高亮；保留/拒绝后 `previousContentRef` 与新基线同步，下一次 Agent 改动不会把已保留的内容误判成未处理；markdown 预览态在预览上方显示同款保留/撤销条。回归用例：`tests/editor-review-e2e.spec.tsx`。

#### 3.8.1 目标

文件被 Agent 或侧边栏保存修改后，在**改动块后面**直接给出：

- **保留**：接受这块改动，保留当前文件内容，清掉待审标记；
- **撤销**：恢复这块改动之前的内容；
- 两个动作之后都能**再撤销**（恢复上一步的文件内容与待审状态）。

不再要求用户先打开 `dsh-diff-approval` 再找 Keep/Revert。

#### 3.8.2 按钮位置（推荐 A）

| 方案 | 位置 | 说明 |
|---|---|---|
| **A. 每个 hunk 末尾（推荐）** | 差异块最后一行下方右侧，一个小操作条：`保留 Ctrl+K` / `撤销 Ctrl+J` | 最贴近“在修改后的栏位后面”；一个文件多个改动块可分别处理 |
| B. 编辑器底部 sticky bar | 编辑器底部固定条，作用于当前文件/当前 hunk | 不随滚动丢失，但和“块后面”不完全一致 |
| C. 复用 `dsh-diff-approval` 面板 | 它已有 Keep/Revert 操作框；只补快捷键与撤销 | 改动最小，但要改另一个插件或通过它的 API 驱动 |
| D. 聊天消息内嵌 diff | 在 Agent 修改消息下面显示 | 需要解析会话事件并渲染 diff，成本最高 |

建议先做 **A**；如果 `dsh-diff-approval` 是唯一可靠的 before/after 来源，则做 **C + 在编辑器显示只读入口**。

#### 3.8.3 快捷键

| 键 | 动作 | 生效范围 |
|---|---|---|
| `Ctrl+K` / `Cmd+K` | **保留**当前 hunk | 焦点在差异块/编辑器，且该块有待审改动 |
| `Ctrl+J` / `Cmd+J` | **拒绝/撤销**当前 hunk | 同上 |
| `Ctrl+Z` / `Cmd+Z` | **撤销上一次保留/拒绝** | 焦点在差异块/编辑器；不抢 CodeMirror 自己的文本撤销 |
| `Ctrl+Shift+Z` / `Ctrl+Y` | 重做上一次撤销（可选） | 同上 |

注意：

- **不要全局绑定**：焦点在聊天输入框/终端时，`Ctrl+K`/`Ctrl+J` 不拦截。
- `Ctrl+K` 与 Cursor 的“内联 AI 改写”冲突；若保留这个键给 Keep，内联 AI 改用 `Ctrl+Shift+K` 或 `Alt+K`。**需确认**。
- `Ctrl+J` 在浏览器里通常是“下载”，DSH 桌面端没有该页面；在编辑器内仍要 `preventDefault`，避免宿主快捷键抢先。
- 操作条按钮本身可点击；快捷键与按钮走同一个 action 函数。

#### 3.8.4 保留 / 撤销 / 再撤销的语义

- **保留**：当前文件内容不变；将该 hunk 标记为已接受；从待审列表移除（或保留为已解决，取决于 `dsh-diff-approval` 的 keep 参数）。
- **apply 后的清理**：点“保留/应用”后，已处理的那部分 diff 从“修改中/待处理”列表里删除；不要继续显示为未处理。撤销该操作时再恢复回来。
- **撤销（拒绝）**：把该 hunk 的旧内容写回文件；未保存的编辑器草稿要先处理（提示“有未保存修改”）。
- **再撤销**：保留/拒绝后，`Ctrl+Z` 恢复动作前的文件内容与待审状态；再 `Ctrl+Shift+Z` 重做。
- 撤销历史：
  - 按文件/会话保存，内存中保留最近 N 步（建议 50）；
  - 刷新/重启后是否保留：建议**不跨重启**，避免和 `dsh-diff-approval` 的持久待审状态冲突；
  - 如果动作来自 `dsh-diff-approval`，优先调用它的 undo/redo，而不是再维护一套。
- 多个 hunk：每个 hunk 独立；另提供“全部保留/全部撤销”（可选）。
- 文件被用户改脏：禁用保留/撤销或提示先保存/丢弃，避免覆盖用户输入。
- 不做静默回退；撤销动作本身可以立即执行，但要有可撤销提示。

#### 3.8.5 与 `dsh-diff-approval` 的关系

- 它是当前最完整的 before/after + Keep/Revert + undo 来源；**优先复用它**，不要建两套 pending 状态。
- 如果它的公开接口足够：
  - 用它列出当前文件的 pending hunk；
  - 调它的 keep/revert/undo；
  - 本插件只负责在编辑器/diff 块后渲染按钮和快捷键。
- 如果接口不够（例如拿不到当前文件 hunk 结构）：
  - 本插件自己记录“上次已读内容”与当前内容，计算行级 diff；
  - 保留/撤销只写文件 + 触发刷新；
  - 明确标注“与 diff-approval 列表不共享”，避免状态漂移。
- 侧边栏保存是否进入它的待审列表：仍按 3.4 的建议，**不默认进入**；行内操作只针对本插件能证明的 before/after。

#### 3.8.6 UI 细节

- 操作条紧贴 hunk 最后一行下方，右侧对齐，不遮挡代码；背景用主题 surface，按钮用次级/危险色。
- 文案：`保留 Ctrl+K` / `撤销 Ctrl+J`；撤销后可显示 `已撤销 · Ctrl+Z 恢复` 的短提示。
- 操作条只在有 pending diff 时出现；hunk 被接受/拒绝后消失。
- 多个 hunk 时，键盘动作作用于**当前聚焦/鼠标所在 hunk**；没有焦点时作用于第一个未处理 hunk（或提示选择）。
- 所有文案进 21 份 locale 词典。

#### 3.8.7 验收

- Agent 修改一个文件 → 每个 hunk 后出现操作条。
- 焦点在 hunk，按 `Ctrl+K` → 该 hunk 标记保留/消失；文件内容不变；`Ctrl+Z` 恢复待审状态。
- 按 `Ctrl+J` → 该 hunk 恢复旧内容；`Ctrl+Z` 恢复修改后的内容。

- 焦点在聊天输入框时，`Ctrl+K`/`Ctrl+J` 不触发。
- 有未保存草稿时，撤销/拒绝先提示，不静默覆盖。

5. 撤销是**只撤销上一次**，还是多步历史？刷新后是否保留？

7. 行内操作是否只对 Agent 修改生效，还是也覆盖侧边栏保存/外部修改？
8. 是否接受“优先复用 `dsh-diff-approval` 的 pending/undo，不在本插件复制一套”？

### 4.1 Ctrl+K 内联 AI 改写（下一轮，MVP）

**目标**：选中代码/当前行，按 `Ctrl+K` 弹出行内输入框，输入指令，模型返回改写，编辑器内显示 before/after diff，用户接受/拒绝。

**MVP 范围**：

- 只处理**当前文件的一处选区**（无选区时当前行），不做多文件/整项目。
- 行内输入框固定在选区上方/下方；`Enter` 提交，`Shift+Enter` 换行，`Esc` 取消。
- 请求内容：文件相对路径、语言、选区行号、选中文本、用户指令、附近少量上下文（前后各 N 行）。
- 模型路由：默认使用当前会话的 provider/model；设置里可固定一个“内联编辑模型”；不可用时显示明确错误。
- Host 侧新增 `edit.suggest` 路由，复用 `ctx.llm.stream`（与 commit message 生成同一套服务）；带超时、取消、token/字符上限。
- 返回：优先要求模型返回**仅替换选区的完整文本**（不返回解释）；客户端用现有 diff 组件做行级 before/after。
- 预览：
  - 内联高亮新增/删除行；
  - 操作：`接受`（写回编辑器草稿，不自动保存）、`拒绝`、`重试`、`复制结果`；
  - 接受后仍是 dirty 草稿，用户再 `Ctrl+S` 保存；不直接落盘。
- 失败/超时/取消：保持原文，显示错误，不修改文档。
- 安全：选区/文件内容上限（如 20k 字符）；不把密钥/凭证发给模型（现有 redact 可复用）；不自动执行命令。
- 不做：多轮对话、跨文件重构、自动应用、Tab 补全、LSP。

**验收**：

- 选中 10 行 → Ctrl+K → 输入“改成 async/await” → 显示 diff → 接受 → 编辑器内容变化、dirty；拒绝 → 原文不变。
- 无选区 → 当前行。
- 模型不可用/超时 → 错误提示，文档不变。
- 取消请求不留下半截文本。
- 不自动保存，不进入 Git 历史。

### 4.2 Ctrl+P 快速打开（第一轮）

- 在侧边栏任意位置（编辑器/文件树聚焦时）按 `Ctrl+P` / `Cmd+P` 打开浮层。
- 模糊匹配**文件名**（v1 不做内容搜索），最近打开的文件优先；最多 50 条。
- 复用 Host `fs.search` 的名称模式与现有 `exclude`/`.ignore` 过滤，不新建索引；超大工作区有超时/截断提示。
- 键盘：`↑`/`↓` 选择、`Enter` 打开、`Esc` 关闭；`Ctrl+Enter` 可“在侧边打开”（可选）。
- 被忽略项不出现；点文件以当前会话的编辑器打开。
- 验收：输入 `foo` 能列出 `src/foo.ts`，回车打开；忽略规则生效；无结果有提示。

### 4.3 文件内查找替换（第一轮）

- 保留现有 `Ctrl+F` 查找；增加替换输入与 `Replace` / `Replace All`。
- 基于 CodeMirror 的 `@codemirror/search`，支持大小写、正则、整词（沿用宿主/CodeMirror 能力）。
- 替换只修改编辑器草稿，不自动保存；`Ctrl+Z` 可撤销。
- 面板样式与现有 top-pinned 搜索面板一致；关闭后编辑器焦点恢复。
- 验收：查找 `foo`，替换一项/全部；撤销恢复；未保存时关闭标签有 dirty 提示。

### 4.6 文件操作统一化：重命名 / 删除 / 上传 / 新建 / 多选（已并入第 5 轮，执行口径以新文档为准）

> **2026-10-18 范围调整**：4.6 的目标保留，但执行口径升级到 [文件浏览器需求](requirements-file-browser-zh.md)：新增列表 / 详细信息视图、拖拽移动 / 复制、复制 / 剪切 / 粘贴、统一右键动作表，以及 `fs.move` / `fs.copy` 宿主路由。本节剩下的表格与细节作为历史设计保留，冲突时以新文档为准。

#### 4.6.1 目标

三种视图（树形 / 图标网格 / Miller 多列）共享**同一套文件操作和选择模型**：同一份操作定义、同一组快捷键、同一套确认与错误提示；所有入口只调用现有 Host 接口 —— `fs.rename`、`fs.remove`、`fs.mkdir`、`fs.createFile`、`/sidebar/upload`，不新增 Host 能力。

#### 4.6.2 现状与差距

| 能力 | 树形 | 图标网格 | Miller 多列 | 工具栏 |
|---|---|---|---|---|
| 重命名 | ✅ 右键 + 行内编辑 | ❌ | ❌ | ❌ |
| 删除 | ✅ 右键 + 确认弹窗 | ❌ | ❌ | ❌ |
| 上传文件/文件夹 | ✅ 工具栏 / 右键“上传到此” / 拖 OS 文件 | 拖拽 ✅，菜单 ❌ | ❌ | ✅ |
| 新建文件/文件夹 | ✅ 右键 + 行内命名 | ❌ | ❌ | ❌ |
| 多选（Ctrl/Shift） | ✅ 含批量条 | ❌ | ❌ | — |
| 快捷键 `F2` / `Delete` | ❌（只有右键菜单） | ❌ | ❌ | — |

结论：**能力都在，入口没铺开**。本轮不新增 Host 逻辑，只做“入口统一 + 选择模型 + 快捷键”。

#### 4.6.3 选择模型（三视图统一）

保持现有手感：**纯单击 = 选中并执行原动作**（树=展开/折叠，网格=进入/打开），修饰键只改变选择、不触发打开。

| 手势 | 行为 |
|---|---|
| 单击行/格 | 选择收敛到该项（单选），并执行原动作（打开/进入） |
| `Ctrl`（macOS `Cmd`）+ 单击 | 切换该项的选中状态，**不打开** |
| `Shift` + 单击 | 从锚点到当前项的区间选择，**不打开**；锚点是最近一次单选 |
| `Ctrl+A` | 全选当前可见行（树=已展开的可见行；网格/多列=当前列） |
| 空白处单击 / `Esc` | 清空选择 |
| 右键未选中项 | 先把选择收敛到该项 |
| 右键已选中项 | 保留多选，菜单出现批量项（删除所选 / 复制路径） |
| 选中 ≥1 项 | 底部（树）或顶部（网格/多列）出现批量条：N 项已选 / 复制路径 / 删除 / 清除 |
| 拖拽选中项 | 全部作为引用拖到聊天（现有 payload 已是数组） |

选择状态以**绝对路径**为 key，跨目录选择在树里天然成立；网格一次只显示一个目录，切目录后选择保留（返回时恢复）；多列视图允许跨列多选，批量条按列分组显示。**（待确认：多列跨列多选是否接受）**

#### 4.6.4 快捷键

| 键 | 动作 | 作用域 | 备注 |
|---|---|---|---|
| `F2` | 重命名 | 文件区聚焦 + 恰好 1 项被选中 | 多选时禁用并提示“请先选中一项” |
| `Delete` | 删除 | 文件区聚焦 + 有选中 | 走确认弹窗，绝不静默删除 |
| `Ctrl+A` | 全选 | 文件区聚焦 | 输入框内不劫持 |
| `Ctrl+Shift+C` | 复制所选路径 | 文件区聚焦 | 与批量条同源；避开编辑器 `Ctrl+C` |
| `Enter` | 打开/进入 | 焦点在项上 | 已有 |
| `Backspace` / `Alt+←` | 返回上级 | 网格/多列 | 已有 |
| `Esc` | 取消行内编辑 / 清空选择 | 文件区 | 已有 |
| `Ctrl+滚轮` | 图标/缩略图缩放 | 网格 | 已有 |

不新增“新建/上传”的全局快捷键：`Ctrl+N`、`Ctrl+Shift+N` 会被 DSH 宿主或浏览器截走，第一版只走工具栏和右键菜单。**（待确认：是否需要 `Alt+N` 之类的插件私有键）**

焦点规则：监听挂在文件区容器上；`event.target.closest('input, textarea, [contenteditable="true"]')` 时直接返回（沿用 `FileTree` 现有写法）；`event.isDefaultPrevented()` 或输入法组合中（`isComposing`）同样返回。

#### 4.6.5 各操作细节

**重命名**

- 入口：`F2`、右键“重命名”、工具栏“重命名”（仅单选可用）、网格/多列的右键菜单。
- 行内编辑：在行/格上就地出现输入框，**预选主文件名、保留扩展名**（`foo.ts` 只选中 `foo`）；`Enter` 提交，`Esc` 取消，失焦提交（VS Code 行为）。
- 客户端先做即时校验（空名、`<>:"/\|?*`、结尾点/空格、Windows 设备名），再交给 Host 复核；Host 的拒绝文案原样展示（沿用 `explorerActionError`）。
- 成功后：已打开的 tab 跟随新路径（`tree-mutations.ts` 现有机制）、选择跟到新路径、滚动位置不动。
- 失败：输入框保持打开、行内红字，不刷新列表。

**删除**

- 入口：`Delete`、右键“删除”、工具栏垃圾桶（仅选中时可用）、批量条“删除所选”。
- 确认弹窗：单个显示文件名；批量显示数量 + 前 5 条路径（其余“等 N 项”）；目录额外标注“文件夹，包含子项会被递归删除”。
- 文案必须说明**不可恢复**（Host 没有回收站）。
- 目标文件在编辑器里有未保存草稿时，弹窗额外提示“该文件有未保存修改”，确认后关闭 tab。
- 成功后：关闭相关 tab、清空选择、刷新当前目录；批量时逐条执行，失败项汇总展示，不回滚（Host 无事务）。

**上传**

- 入口：工具栏两个按钮（文件 / 文件夹）、右键“上传到此”、把 OS 文件/文件夹拖到网格、多列或树行。
- 目标目录：右键目录项 = 该目录；右键文件 = 其所在目录；空白处 = 当前目录。
- 冲突策略：现状是**同名覆盖**（临时文件 + rename，后写入者生效）。本轮保持覆盖，但完成后提示“已覆盖 N 项”；三选（跳过/覆盖/重命名）放到下一版。**（待确认）**
- 进度：复用 `UploadOverlay`；多文件串行，失败项列在结果里，不中断其余文件。
- 上传完成后刷新目标目录；新上传的项保持选中/高亮。

**新建**

- 入口：右键“新建文件 / 新建文件夹”、工具栏两个按钮、网格空白区右键。
- 就地命名，默认名走 i18n（`untitled` / `新建文件夹`），重名自动避让 `untitled-1`、`untitled-2`。
- `Enter` 创建：文件 → 直接打开；文件夹 → 进入（网格/多列）或展开（树）。
- 校验与重命名共用一套（单段名、非法字符、重名由 Host 拒绝）。

**多选与批量**

- 批量操作：删除、复制路径、拖到聊天（多条 `@` 引用）、拖到 `.ignore` 眼睛（现有单条，扩展为批量追加）。
- 批量删除逐条串行，避免并发打爆 Host；完成后汇总“成功 N / 失败 M”。
- 不做批量重命名。

#### 4.6.6 工具栏改造

- 现状：刷新、视图切换、`.ignore`、排序、上传文件、上传文件夹。
- 新增：新建文件、新建文件夹（常驻）；重命名、删除（有选中时启用）；空间不足时收进 `⋯`。
- 实现建议：抽一份**操作描述表** `fileActions`（`id` / `label` / `icon` / `shortcut` / `enabled(selection)` / `run(ctx)`），树、网格、多列、工具栏、右键菜单都从这一份渲染。现在三处右键菜单各写了一遍，正好一起收口。

#### 4.6.7 技术要点

- 只复用 `api.fsRename` / `fsRemove` / `fsMkdir` / `fsCreateFile` / `uploadFile`，不新增 Host 路由。
- 新增客户端 hooks：`useFileSelection(items, { multi, range })`、`useInlineEdit()`、`useFileActions(scope, dir, selection)`。
- 网格与多列的条目都是 `FsEntry`，选择 key 用绝对路径；渲染顺序即 Shift 区间顺序。
- 行内编辑复用树的现有实现（`FileTree` 里的 `rename` / `newFolder` / `newFile` 输入框），抽成组件再挂到网格/多列，避免复制三份。
- 无障碍：行/格加 `aria-selected`；批量条 `role="toolbar"`（树已有）。
- i18n：复用 `rename` / `delete` / `deleteSelected` / `newFile` / `newFolder` / `uploadHere` / `copyPaths` / `filesSelected` / `clearSelection`；新增键（如“请先选中一项”“已覆盖 N 项”）进 21 份词典。

#### 4.6.8 验收

- 三种视图里 `F2` 都能就地重命名，扩展名不被选中，`Enter` 生效、`Esc` 放弃。
- `Delete` 弹确认，确认后文件消失、相关 tab 关闭；取消则无变化。
- 网格/多列右键菜单包含打开/引用/复制路径 + 上传到此/新建文件/新建文件夹/重命名/删除。
- `Ctrl+`单击可加选、`Shift+`单击可区间选，`Ctrl+A` 全选当前可见项，`Esc` 清空。
- 批量条显示正确数量，批量删除只确认一次并汇总失败。
- 拖 OS 文件到网格/多列/树行能上传到目标目录，冲突覆盖后有提示。
- 所有新文案进入 21 份 locale；类型检查、单测、mount lane 通过。

## 6. 总验收清单

- [ ] `Ctrl+L` / 拖动 / 按钮三种入口统一为 `@文件 line X-Y`，不含代码正文。
- [ ] 无选区时是当前行；Markdown 预览无法定位行号时退化为 `@file`。
- [ ] 改动块后出现“保留 / 撤销”；`Ctrl+K` 保留、`Ctrl+J` 拒绝；`Ctrl+Z` 可撤销上一步。
- [ ] 保留/应用后，已处理的那部分 diff 从待处理列表删除；撤销后恢复。
- [ ] 文件浏览器支持树形/图标切换；图标网格第一格是“返回”，文件夹可进入，文件可打开/引用/复制路径。
- [ ] 行内操作不会覆盖未保存草稿；多个 hunk 独立处理。
- [ ] 忽略图标可用，支持拖拽、多选、右键、`.ignore` 实时读取、导入其他 ignore。
- [ ] 忽略只影响侧边栏，不影响磁盘和 Git。
- [ ] 自动 diff 默认 banner + 角标；Diff 面板默认停靠 DSH 原生右侧栏 tab，不浮层、不占底部；View/Keep/Revert 可用；无 diff-approval 时降级。
- [ ] `Ctrl+P` 快速打开、文件内查找替换可用。
- [ ] 三视图统一的文件操作：`F2` 重命名、`Delete` 删除（走确认）、右键“上传到此”、新建文件/文件夹、`Ctrl`/`Shift` 多选与批量条。
- [ ] 网格/多列右键菜单与树一致；批量删除只确认一次、逐条执行并汇总失败。
- [ ] 新增列表 / 详细信息视图（或按确认结果落地的视图），四种视图共享选择、右键、拖拽与快捷键。
- [ ] 内部拖拽可移动 / 复制到文件夹行、面包屑、列头、空白区；冲突不静默覆盖；OS 文件可拖入任一视图上传。
- [ ] 右键菜单由同一份动作表生成；文件 / 文件夹 / 空白区 / 多选各有完整菜单，键盘可达、视口内翻转。
- [ ] 复制 / 剪切 / 粘贴、`F2` / `Delete` / `Ctrl+A` / `F5` 在四种视图中一致可用；失败有可见错误与批量汇总。
- [ ] （下一轮）`Ctrl+K` 内联 AI：如果 `Ctrl+K` 已给“保留”，需换键。
- [ ] 所有新增文案进入 20 份 locale 词典（zh / en + 18 种第三方；见新文档 §4.12）。
- [ ] 类型检查、单测、真实浏览器 mount lane 通过。

## 7. 需要你确认的问题（剩余）

1. **行内按钮位置**：每个 hunk 最后一行下方（推荐）、编辑器底部固定条，还是 `dsh-diff-approval` 面板里？
2. **作用粒度**：保留/撤销按 **hunk**（推荐）还是整个文件？
3. **`Ctrl+K` 冲突**：确定把 `Ctrl+K` 给“保留”吗？那内联 AI 改写改用哪个键（`Ctrl+Shift+K` / `Alt+K`）？
4. **`Ctrl+J`**：接受“拒绝”用 `Ctrl+J` 吗？浏览器下载/编辑器 join-lines 的冲突是否需要换键？
5. **撤销范围**：只撤销上一步，还是多步历史？刷新/重启后是否保留（建议不跨重启）？
6. **拒绝语义**：直接写回文件，还是只回退编辑器草稿？有未保存修改时如何提示？
7. **状态来源**：优先复用 `dsh-diff-approval` 的 pending/undo（推荐），还是本插件自己维护 before/after？
8. **触发源**：行内操作只对 Agent 修改生效，还是也覆盖侧边栏保存/外部修改？
9. **Diff 停靠位置**：确认是 **DSH 原生右侧栏**（`sidebar.right.pane.tab`，和 Files/Git 同一列），不是插件底部工作台/浮层？
10. **自动展开**：变更时只显示 banner/角标、点击再展开右侧栏（推荐），还是变更时自动展开 Diff tab？
11. **忽略规则写入位置**：手动忽略写根 `.ignore`（推荐，可共享），还是插件数据（不污染工作区）？
12. **“显示被忽略项”记忆**：按工作区记忆（推荐），还是只当前会话临时生效？
13. **导入范围**：导入 `.gitignore` / `.cursorignore` 时，整份复制还是只根目录规则？建议整份复制 + 去重。
14. **自动 diff 触发源**：Agent 修改 + 侧边栏保存（推荐），还是只 Agent？外部修改只角标、不弹 banner，是否接受？
15. **默认视图**：保持现状的图标网格（新文档推荐）还是恢复树形默认？视图是否按工作区记住？
16. **返回位置**：图标网格第一格“返回”（你要求的），是否同时保留顶部返回/面包屑按钮？
17. **单击/双击**：文件夹单击进入、文件单击打开（推荐侧边栏手感），还是桌面式双击打开？
18. **图标视图操作范围**：先做打开/进入/返回/引用/复制路径，还是一次补齐重命名/删除/上传/新建？
19. **优先级**：是否按“Ctrl+L → 行内保留/撤销 → 忽略入口 → 自动 Diff（右侧栏） → 文件浏览器完善（新文档 A → B → C：统一入口 → 文件搬运 → 列表视图） → Ctrl+P/查找替换 →（下一轮）内联 AI”实施？
20. **文件操作手势**：单击是否保持“选中 + 打开”？`Ctrl`/`Shift` 单击只改选择、不打开，是否接受（见 4.6.3）？
21. **文件操作快捷键**：`F2` / `Delete` / `Ctrl+A` / `Ctrl+Shift+C` 之外，新文档还要求 `Ctrl+C/X/V`、`F5`、`Shift+F10`、方向键焦点（见新文档 §4.9），是否全部接受？
22. **上传同名**：保持覆盖（现状）/ 跳过 / 每次询问？覆盖后是否要“已覆盖 N 项”提示？
23. **多列多选**：多列视图允许跨列多选（批量条按列分组），还是只允许同列多选？
24. **批量删除失败**：接受“不回滚、逐条报告”吗（Host 无事务）？
25. **文件复制/剪切/粘贴**：~~本轮是否要做？建议不做，先完成重命名/删除/上传/新建/多选。~~ **2026-10-18 已升级为正式需求**，见 [新文档](requirements-file-browser-zh.md) §4；待确认的是「插件内剪贴板、不接系统文件剪贴板」是否接受。
26. **文件浏览器视图**：是否新增列表 / 详细信息视图？还是只补齐树 / 网格 / 多列？（推荐新增，见新文档 §1）
27. **拖拽默认**：默认移动、`Ctrl` 复制是否接受？同名冲突默认「保留两者 / 跳过 / 取消」怎么选？（见新文档 §2）
28. **第 5 轮剩余默认值**：视图 / 排序按工作区记忆、插件内剪贴板、删除永久、`fs.move` / `fs.copy` 路由命名——是否全部按新文档 §9 的推荐默认执行？

> 如果以上默认方案都同意，回复“按默认”即可；行内保留/撤销建议先做，因为它是当前最影响使用的缺口。
